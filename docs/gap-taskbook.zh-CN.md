# 生成任务书与实时角色状态

NumPilot 将缺口转换为模型和开发者共用的任务书：描述实现要求、已知事实、待确认条件和验收方法。
任务书本身不授予算子或程序资格。

## 六角色的工作分工

Analyzer 采集调用事实；Planner 组织任务；API Gap Filler 生成候选；Code Migrator 使用已准入接口
改写程序；Diagnostics 定位失败；Reporter 保存产物。API 正确性与全程序验证是确定性步骤。

终端即时显示当前角色、活动、执行方式、尝试次数和耗时。TTY 使用六行状态面板，非 TTY 使用
即时刷新的消息；支持 JSON 的命令保持 stdout 纯净。角色区分规则处理、真实模型调用和外部代理。
未执行的角色不会伪装成调用过模型；等待外部实现显示阻塞，不显示为远端仍在生成。

子进程通过专用生命周期事件通道传递状态。原始模型输出、源码和 stderr 不被当成角色事件。
UI 故障不改变迁移结论。`run` 保存 `workflow-progress.jsonl`，正式资格仍以独立回执为准。
性能命令使用入口/出口消息，避免动态面板刷新干扰测量。

## 用户拿到什么

每个缺口工作目录中会有 `GAP_TASKBOOK.md` 和 `GAP_TASKBOOK.json`，分别供人阅读和程序处理。
`complete-gaps` 在配置探测与模型调用前保存所有缺口任务书，模型无法连接或生成失败时仍保留。
合同迁移在报告目录保存分析阶段草案。独立 adapter 命令在同级 `<out-name>-taskbook` 保存任务书；
外部 handoff 和新 adapter 候选内有对应的 `taskbook/`，同份内容进入每个文件的生成提示。

文件采用内容身份和 SHA-256 绑定。同内容可复用，不同内容不可覆盖；修改需求使用新运行目录。
历史候选复用不会被追认为“原模型已经读取了新任务书”。

## 任务书内容

| 内容 | 必须回答的问题 |
| --- | --- |
| 缺口与来源 | API、AsNumpy目标、源文件与SHA、调用行列、缺失或契约不满足原因 |
| 调用契约 | 参数与静态字面量、已有签名；dtype/shape/轴/广播/布局/返回结构的已知与未知 |
| NumPy语义 | 类型提升、NaN/Inf、正负零、空数组、异常、out/别名等行为 |
| 支持范围 | 本批最小实现范围、拒绝输入、尚待收集的运行时profiles |
| 接入依赖 | 官方优先路线、AsNumpy源码绑定、CANN/SoC、Skill和后续证据引用 |
| 验收 | NumPy oracle、可复现输入、误差、构建/加载、真实NPU、原程序回归、独立性能 |

早期任务书绑定原源码和 GapSpec。静态调用不等于已经执行的输入 profile；没有实际证据时，
dtype、shape、布局、输出与误差标准明确为 unknown 或待确认。尚未解析的 AsNumpy/Skill/官方接口
列为依赖，后续上下文包提供实际内容哈希。需求和建议不能冒充已通过的验证。

## 当前聚焦 float32

候选目标限定为 float32 tensor 输入。显式要求其他输入 dtype 时，先保存阻塞任务书，再拒绝生成；
不得偷偷转换输入或扩大支持。比较算子的布尔输出等固有语义照常保留。
`runtime_profile_required` 是需要收集 profile 的标记，不是 dtype。

未知 shape 不意味着支持所有 shape。生成者需提出最小支持与拒绝范围，再由真实输入和测试确认。
只有精确调用通过资格检查后才能用于严格 NPU 迁移。

## 模型卡住时手工继续

1. 阅读任务书及绑定 GapSpec，确认 float32 签名和未知项，补齐可复现输入与验收标准。
2. 按源码上下文和协议实现候选。外部 adapter handoff 使用 README 指定的 prompts/、responses/
   和响应格式；不修改固定 AsNumpy 组件或已绑定的需求文件。
3. 将候选交回相同的解析、构建、加载、NumPy 对拍与 NPU 验证。手工代码同样保持
   generated_unverified，通过全部门禁后才取得限定资格。
4. 失败保留原记录，用新目录或正式修复流程继续；生成文本成功不等于算子成功。

任务书降低需求传递的歧义，不保证每个缺口都能一次实现。
