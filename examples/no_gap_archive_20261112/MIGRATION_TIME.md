# 迁移耗时：框架实测 vs 人工估算（2026-11-12）

## 1. 框架实测

- 范围：71 个无缺口 NumPy 程序，2107 行源码（平均 29.7 行/例），
  1078 个调用点改写（平均 15.2/例，最多 148）。
- 全流程：prepare → analyze → plan → LLM 迁移 → 执行 → 数值验证 →
  （必要时）修复；真实模型 deepseek-flash。
- 总耗时：363.22 s = 6.05 min。
- 单例：平均 5.12 s，中位数 2.72 s，P90 13.04 s，最大 23.55 s
  （C014_logistic_training）。
- 单位改写：0.337 s/调用点。
- 修复：70/71 零修复；H012_logarithmic_grid 1 次修复。

## 3. 边界

- 人工数字是参数化估算，不是实测；用于量级对比，不作为精确承诺。
- 估算假设已熟悉 AsNumpy/CANN；若包含学习成本，人工耗时会更高。
- 框架耗时包含真实模型调用与执行验证，不是纯代码生成时间。
- 71 例为小规模正确性程序；更大程序的单例耗时会上升，但单位改写
  成本预计保持同一量级。
